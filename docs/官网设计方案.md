### 5.2 采纳方案（推荐）

**以 B 为骨架，A 为血肉**：
- 页面骨架、圆角、间距、字体、交互反馈 → 全部沿用 **B（参考站设计系统）**，保证「干净、克制、苹果式」的高级感
- 主强调色 → 采用 **`#0066cc`**（与参考站一致，视觉统一、更现代）
- 深色区块（关于/CTA/页脚暗区）→ 用 **A 的深空蓝 `#142848`**，保留公安蓝的权威性
- 3D 发光与数据高亮 → 用 **A 的高亮青蓝 `#50AAFF`**

> 两套色板同属蓝色系，`#0066cc` 与 `#1E64C8` 色相接近，混用协调无冲突；且参考站已验证该组合在浅色下的可读性。

### 5.3 字体（与参考站一致）
- 中文：`PingFang SC` → `Hiragino Sans GB` → `Noto Sans SC` → `Microsoft YaHei`
- 西文/数字：`-apple-system / SF Pro` → `Arial`
- 字重：标题 650–700，正文 400；标题 `letter-spacing: -0.02em ~ -0.03em`

### 5.4 组件规范
- 圆角：卡片 18px，按钮 pill，大区块 28px
- 阴影：`0 16px 40px -18px rgba(20,40,72,.22)`，禁止纯黑阴影
- 栅格：12 列，内容宽 `1120px`，宽版 `1280px`，移动端断点 1000 / 720px
- 间距基数：8px；区块间距 96px（移动端 68px）

## 6. Three.js 动效设计

> 原则：**服务内容**，不炫技拖慢加载；移动端降级；无障碍支持 `prefers-reduced-motion`。

### 6.0 与参考站动效方案的取舍（重要）

| 维度 | 参考站做法（已核实） | 本方案（Three.js） |
|---|---|---|
| 技术 | **零依赖 Canvas 2D**，`hero-tech.js` 单 rAF 驱动两画布 | Three.js（WebGL） |
| 内容 | 1) 粒子网格 + 神经网络光流  2) 全息人形机器人线框 | 真 3D 低空防御穹顶 + 产品场景 |
| 体积 | ~0 KB 依赖 | three.module.js 约 150KB（gzip） |
| 观感 | 伪 3D，透视靠 2D 投影绘制 | 真 3D，可旋转/景深/光照 |
| 稳健性 | DPR≤2、移动端粒子降至 40、出视口停车 | 同样策略 + `import()` 失败自动降级 Canvas 2D |

**结论（推荐混合方案）**：
- **首页 Hero** → 用 **Three.js** 做真 3D（低空防御穹顶），这是「升级点」，值得 150KB
- **产品页 3 个场景** → 按需异步加载；移动端或低端设备**降级为 Canvas 2D / 静态图**
- **滚动微动效** → 用 CSS + IntersectionObserver（零成本），不引入 GSAP
- **失败兜底** → `import('three')` 失败时自动切 Canvas 2D，页面绝不空白（预览稿已实现该兜底）

### 6.1 场景清单

| 位置 | 场景 | 视觉描述 |
|---|---|---|
| 首页 Hero | **低空防御穹顶** | 双层线框穹顶（自转）+ 地面网格 + 三区三防同心环（呼吸）+ 16 个无人机节点沿轨巡航并投下垂线 + 上下扫描环 + 鼠标视差 |
| 产品 DX | **三维电子沙盘** | 线框地形起伏 + 航线轨迹 + 三区（管控/预警/防范）分层辉光 |
| 产品 RX | **多智能体协同网络** | 空间节点群 + 动态连线 + 脉冲信号沿链路传递 |
| 产品 EX | **知识图谱星云** | 六维标签节点 + 关联连线 + 粒子扩散 |
| 全局 | **滚动微动效** | 区块淡入上移、数字滚动计数 |

### 6.2 性能策略（沿用参考站经验）
- Three.js 按需异步加载（`import()`），Hero 优先，其余进入视口再初始化
- `devicePixelRatio` 上限 **2**（参考站同款策略，避免 3x 屏 4 倍绘制）
- 移动端粒子/节点数压缩；几何体与材质复用
- 页面隐藏 / 场景滚出视口 → 渲染循环停车
- `prefers-reduced-motion` → 只渲染一帧静态画面
- `window.devicePixelRatio` / 视口变化 → 节流 resize

## 7. 技术方案：方案 B（Vite + 原生 JS + Three.js）

| 层 | 选型 | 说明 |
|---|---|---|
| 构建 | **Vite 5/6** | 多页应用（MPA）配置，SEO 友好，产出静态文件 |
| 语言 | 原生 JavaScript（ESM） | 轻量，无框架负担；如需可上 TypeScript |
| 3D | **Three.js** | Hero 与产品视觉场景 |
| 动效 | 原生 `IntersectionObserver` +（可选）GSAP | 滚动动画 |
| 样式 | 原生 CSS + CSS Variables | 主题令牌集中管理（见第 5 节色板） |
| 组件化 | 原生 JS 模板函数 + 数据驱动渲染 | `data/products.js` 统一管理产品数据，页面复用 |
| 路由 | MPA 多 HTML 入口 | 每个页面独立 HTML，利于 SEO 与分享 |
| 部署 | GitHub Pages | 可走 `gh-pages` 包或 GitHub Actions |

**为什么 MPA 而非 SPA**：官网以内容展示与 SEO 为重，多页静态产出更利于搜索引擎收录与首屏速度。

## 9. 部署流程（GitHub Pages）

1. 本地 `npm run build` 产出 `dist/`
2. 推送仓库（建议 `zhongdun-website`）
3. 二选一：
   - **Actions**：`main` 分支推送自动构建并发布（推荐）
   - **gh-pages 分支**：`npm run deploy` 推送 `dist/`
4. Settings → Pages → 选择源
5. （可选）绑定自定义域名 + HTTPS

> 注：若为项目仓库（非用户名仓库），需在 `vite.config.js` 设置 `base: '/<repo>/'`。

### 11.1 技术栈实况

| 项 | 实况 |
